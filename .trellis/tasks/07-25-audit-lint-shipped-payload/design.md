# Design — Lint gate for shipped payload Python

## Scope

Bring the pack's only consumer-shipped executable,
`templates/skills/se-review-skills/scripts/skill_review.py`, under the same
ruff + mypy gate as the rest of the repo's own Python, and fix the three
defects the tools already report on it.

Files that change:

1. `Makefile` — the `lint` target (ruff + mypy command lines).
2. `.github/workflows/tests.yml` — the CI `lint` lane (ruff + mypy steps), kept
   scope-identical to the Makefile so local and CI enforce the same set.
3. `templates/skills/se-review-skills/scripts/skill_review.py` — three defect
   fixes. This is a shipped-payload edit, so release discipline applies.
4. `manifest.json` — `version` bump.
5. `CHANGELOG.md` — matching top heading.
6. `templates/skills/_shared/references/skill-catalog.md` — regenerated by
   `make generate` to carry the new version (the only generated surface that
   changes for a pure version bump).

## Gate scope decision

The current lint scope is `install.py installer tests .github/scripts` (ruff)
and `installer install.py` (mypy) — the shipped `templates/**` payload is
unlinted today. Add the single file
`templates/skills/se-review-skills/scripts/skill_review.py` to both tools in
both surfaces. It is the only `.py` under that scripts directory, so a file
path and a directory path are equivalent today; the explicit file path matches
the PRD evidence and states intent precisely.

ruff config (`pyproject.toml`) already selects rule family `B` (covers B905)
and applies no `templates/**` exclude; mypy config sets no excludes. No config
change is needed — only the command scope.

## A-026 wrapper coordination

The repo-root wrapper `scripts/se-ai-command-pack-skill-review.py` is a
runpy forwarder flagged as dead code. Its keep-vs-delete disposition is owned
by a **separate** task (`07-25-audit-repo-tooling-ownership`, ledger A-026),
not this one. Per this PRD's coordination clause ("include … only if it is
kept"), the wrapper is **excluded** from this task's lint gate: adding it would
prejudge the "kept" outcome. When A-026 resolves to keep + document it as the
supported repo-root entry point, adding it to the gate travels with that
decision. Recorded as a follow-up pointer, not new work here.

## The three defects and their fixes

1. **ruff B905 at :297** — `zip(shared.keys, shared.values)` iterates the
   parallel key/value lists of an `ast.Dict`. **The obvious `strict=True` fix is
   wrong here:** this shipped analyzer documents a Python 3.9 runtime floor
   (`SKILL.md`: "Python 3.9 or newer"; `MINIMUM_PYTHON == (3, 9)`), and
   `zip(strict=)` is 3.10+. An existing regression test
   (`tests/test_skill_review.py::test_analyzer_keeps_the_documented_python_39_runtime_floor`)
   asserts `assertNotIn("strict=True", source)`, so a `strict=True` fix would
   fail `make check`. The B905 finding only appears because the repo-wide ruff
   target is `py310`; under `--target-version py39` the file is already clean.
   Fix by removing `zip` entirely — index the parallel lists via
   `enumerate(shared.keys)` / `shared.values[index]`. This is 3.9-safe,
   structurally eliminates B905 (no `zip`, no `strict=`), preserves the guard
   test, and is behavior-identical (`ast.Dict.keys`/`.values` are equal-length
   parallel lists).

2. **mypy `[assignment]` at :268** — the walrus binding `value` in the
   comprehension at :257–260 leaks into the function scope as `str | None`;
   the loop then rebinds `value = _assignment(...)` (`AST | None`) at :268,
   which mypy rejects as an incompatible reassignment. Fix by renaming the
   loop-local to `assignment_node` (used at :268, :269, :271) so the two
   bindings no longer collide. Pure rename, no behavior change.

3. **mypy `[arg-type]` at :673** — inside `if manifest_mapping:` the code sets
   `context = context_hint` (`PackageContext | None`) and passes it as
   `ResolvedSkill` arg 3, which requires `PackageContext`. `manifest_mapping`
   is truthy only when `context_hint is not None` (see the guard at :652), so
   the value is always non-None here, but mypy cannot infer that cross-variable
   invariant. Fix by narrowing the guard to
   `if manifest_mapping and context_hint is not None:` — logically redundant,
   behavior-preserving, and gives mypy the narrowing it needs.

## Release discipline

Editing `templates/**` is a shipped-payload change: bump `version` in
`manifest.json` and add a matching `## <version> - YYYY-MM-DD` heading to
`CHANGELOG.md`. These are defect fixes with no feature or interface change, so
a patch bump (`0.66.1` → `0.66.2`) is correct. The CI release-payload gate
enforces this.

The version also feeds generated surfaces: `generate-skill-surfaces.py` renders
`Bundled pack version: \`<version>\`` into
`templates/skills/_shared/references/skill-catalog.md`, and `make release-check`
runs the generator with `--check`, failing on any drift. So the bump is not
complete until `make generate` regenerates those surfaces. Run `make generate`
after editing `manifest.json` and commit every file it rewrites
(`skill-catalog.md` and any README/overlay the generator touches for the version
change). Otherwise `make check` fails at `release-check`.

## Compatibility / rollback

No behavior change to `skill_review.py`: the B905 fix swaps `zip` for an
equal-length indexed traversal (same iteration order and results), and the two
mypy fixes are a rename and a redundant guard. All three stay within the 3.9
runtime floor. The gate additions only widen enforcement. Rollback is a
straight revert of the branch; no data or interface migration is involved.

## Validation

- `make lint` — ruff + mypy over the widened scope; expect clean.
- `make check` — full gate (test + lint + release-check); expect green,
  including the release-payload gate now that version + changelog moved.
