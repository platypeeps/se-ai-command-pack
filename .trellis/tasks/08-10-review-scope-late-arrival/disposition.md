## The fix

`--prepare-tooling-body` appended the scope section only when **every** changed
path was generated or repository bookkeeping. On a mixed diff it exited `3` and
wrote nothing — leaving the body without a heading in exactly the case that
needs one. Observed on PRs #156, #163, #172, #203 and #208.

The refusal was a **truthfulness guard**, not an oversight. The canned section
claims the change is *limited to* generated surfaces, which is false when
authored files are present. So the fix is a text change first and a
control-flow change second, which is why the tooling-only text is byte-for-byte
unchanged and only the mixed case gets new wording.

A mixed diff now gets a section naming only the paths proven to be generated:

```
Tooling/generated scope:

- Generated or repository-bookkeeping paths in this branch include:
  - ".trellis/workspace/dev/index.md"
  - ".trellis/workspace/dev/journal-4.md"
- Remaining changes are authored and reviewed normally.
```

Worded `include:` deliberately. The branch acquires further generated files
after this body is written — that is the whole defect — so any exhaustive claim
would be false by the time the gate reads it.

The contract on a non-empty changed set:

| `matched` | `unmatched` | Status | Body |
| --- | --- | --- | --- |
| none | any | `3` | unchanged |
| some | none | `0` | exhaustive section (**text unchanged**) |
| some | some | `0` | **new** enumerating section |

Exit `3` survives with a narrower, honest meaning: *nothing to declare*.

The decisive mechanical fact is that **`pack.review-scope` itself is
unchanged**. `github_pr_body_mentions_scope` tests for heading *presence* and
never checks that the declared paths correspond to the triggering ones, so a
heading written at PR-creation time satisfies the gate at the finalization
head. The gate script was not touched, weakened, or made aware of this fix.

## Why this does not weaken the gate

Three arguments, of which the third is decisive:

1. A diff with no generated path still writes nothing (`matched` empty still
   exits `3`), so an unexplained generated change still reaches the gate
   undeclared and still fails. It has its own test.
2. The enumeration is strictly *more* informative than what it replaces:
   previously an operator hand-pasted a canned sentence naming no paths at all.
3. Human-authored PR bodies never enter preparation mode. `sd-create-pr`
   forbids automatic preparation against a user-provided body for byte-for-byte
   preservation — `templates/docs/SD_AI_COMMAND_PACK.md`, "User-provided bodies
   never enter this preparation mode and remain byte-for-byte subject to the
   existing validator" — so a custom body remains subject to the strict
   validator unchanged. (Cited by phrase, not line: the first draft of this file
   said line 828, and the same commit's own edits moved it to 834.)

## Residual gap, accepted knowingly

A branch whose PR-creation diff contains *zero* generated paths but acquires
journal/index files at finalization is **still uncovered**. Closing it would
require the preparer to assert a future diff — to declare paths it cannot
prove — which is the truthfulness guard the fix was careful to preserve.

All five observed PRs carried `.trellis/tasks/**` at creation, so all five are
covered. The residual case is documented in the spec with the manual workaround
kept alive for it, rather than reported as closed.

## Security review of the new output

Enumerated paths are repository-controlled text that lands in a **published**
PR body, so two hardening decisions were made deliberately rather than
discovered later:

- Each path is escaped with `json.dumps(path, ensure_ascii=True)`, matching the
  existing diagnostic idiom in the same file, so a newline or Markdown
  metacharacter in a filename cannot inject structure into the body. It has its
  own test.
- The list is capped at `MAX_ENUMERATED_SCOPE_PATHS = 20` with an explicit
  `...and N more` remainder rather than truncated silently. It has its own
  test.
