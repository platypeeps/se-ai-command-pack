# Research: Agent install/remove + test surfaces to extend

- **Query**: How do agents install/remove via manifest.json + installer? Which test files must be extended for new agents, RuntimeProfile/delegation, registry snapshot, drift/release gates?
- **Scope**: internal
- **Date**: 2026-08-05

## Findings

### Manifest rows for agents

Agent rows are generated by `build_agent_rows()` (`.github/scripts/generate-skill-surfaces.py:890-911`) and appended in `build_rows()` (`:954`). se-smoke's committed rows (`manifest.json:4868-4886`):

```json
{ "platform": "claude", "kind": "agent", "scope": "user",
  "source": "generated/agents/claude/se-smoke.md",
  "target": ".claude/agents/se-smoke.md",
  "anchor": ".claude", "install": "if-anchor-exists" },
{ "platform": "codex", "kind": "agent", "scope": "user",
  "source": "generated/agents/codex/se-smoke.toml",
  "target": ".codex/agents/se-smoke.toml",
  "anchor": ".codex", "install": "if-anchor-exists" }
```

Two rows per agent (claude + codex; Amp excluded). Two new agents → 4 new manifest rows, plus 4 new `generated/agents/**` files. These regenerate via `make generate`; never hand-edited.

### Install path

- `KNOWN_MANIFEST_KINDS` (`installer/manifest.py:34-45`) already includes `"agent"` — no installer change needed for the kind.
- Agents are ordinary manifest rows; `install.py`/installer copy them to `PlatformInfo.agents_dir` (`~/.claude/agents/<name>.md`, `~/.codex/agents/<name>.toml`) under `if-anchor-exists`. No agent-specific install branch — they flow through the generic manifest-driven install/provenance/receipt path.

### Remove path

- Removal is provenance/receipt-driven (see docs `SE_AI_COMMAND_PACK.md:888-892`): a candidate is deleted only when it is a recognized pack target and its hash matches. New agents remove automatically once installed via their provenance entries.
- `RETIRED_TARGETS` in `installer/removal.py:49-56` is only for skills/agents **removed from a shipping manifest** (currently only `.config/agents/skills/se-pack/SKILL.md`). New agents do **not** touch `RETIRED_TARGETS` on add. (Relevant only if se-smoke is retired — the canonical se-smoke says "Remove this agent when the first real worker role ships"; if this task deletes se-smoke, its two last-shipped install targets (the retired se-smoke Claude agent MD and Codex agent TOML) would be added to `RETIRED_TARGETS`, per docs "Retiring an agent" `:991-995` + "Retiring a skill" step 3 `:967-969`.)

### Test surfaces to extend

**`tests/test_generate.py`** — agent render/validation/drift:
- `RealRepoAgentTest` (`:557-597`): `test_committed_agent_overlays_match_canonical` (`:560`) iterates every `regenerated_agent_texts()` — passes automatically for new agents once committed. `test_agent_rows_only_on_agent_capable_platforms` (`:566`) asserts agent-row platforms == `{"claude","codex"}`. `test_amp_receives_no_agent_rows` (`:573`). `test_smoke_agent_round_trips_through_both_dialects` (`:583`) is se-smoke-specific — **must be updated/replaced if se-smoke is retired**, or add analogous round-trip tests for the two new agents.
- `AgentRendererTest` (`:600-657`): dialect/escaping guarantees using a synthetic `se-fixture` — `test_claude_keeps_portable_keys_and_drops_sandbox_mode` (`:620`), `test_codex_toml_escapes_and_preserves_body` (`:633`), `test_codex_omits_absent_optional_hints` (`:644`). Fixture-based; no change needed unless new hint behavior.
- Generator-flow fixture tests using `write_agent()` helper (`:1317-1330`): `test_generate_writes_agent_overlays_and_rows` (`:1332`), `test_check_detects_agent_drift` (`:1348`), `test_generate_removes_unexpected_agent_file` (`:1359`), `test_agent_with_banned_phrase_is_rejected` (`:1369`). Fixture-based; unaffected, but a new agent-body-validation test (e.g. governance-invariant presence) would go here if design adds any check.

**`tests/test_install.py`** — install/remove round trip:
- `AGENT_ROWS = [row for row in MANIFEST["files"] if row["kind"] == "agent"]` (`:331`).
- `test_no_agent_row_targets_the_amp_anchor` (`:337`).
- `test_agent_round_trip_on_claude_and_codex` (`:344-369`): **hard-coded to se-smoke** — asserts the se-smoke Claude agent MD plus Codex agent TOML install, appear in installed-targets/receipt/provenance, then remove. Must be updated to the new agent names if se-smoke is retired.
- `test_installed_codex_agent_is_valid_toml` (`:372-377`): hard-coded se-smoke TOML parse (`parsed["name"] == "se-smoke"`). Same update need.

**`tests/test_release_gate.py`** — payload/version gate: `generated/**` and `installer/**` changes require a version bump + dated changelog (`test_generated_payload_change_without_bump_fails` `:85`, `test_installer_change_with_bump_passes` `:165`). Adding agents/registry changes = payload change → **requires `manifest.json` version bump (from 0.66.12) + a dated `CHANGELOG.md` heading**. No new test needed unless behavior changes; but the gate will fail the task's own diff if the bump/changelog is missing.

**`tests/test_management.py`** — `test ... "platforms: agents, claude, codex"` (`:35`) status string; unaffected by agents unless status output changes.

**`tests/test_skill_review.py`** — registry-snapshot consumption (`:222+`, `write_snapshot` `:232`, `test_snapshot_preferred_matches_ast_fallback` `:241`). Only relevant **if** delegation is added to the snapshot schema (it is not today — see `registry-delegation.md`). If the snapshot schema is bumped, these tests and `SUPPORTED_REGISTRY_SNAPSHOT_SCHEMA_VERSIONS` must change.

**Registry validation tests**: registry invariants are exercised at import (`validate_registry()` runs on import, `registry.py:654`). A delegation axis with a new `validate_runtime_profile` row is covered indirectly by any test importing the registry. There is no dedicated `test_registry.py`; `RuntimeProfile`/`validate_runtime_profile` are not directly grep-hit in `tests/` — coverage is via `test_generate.py` fixtures (`gen.RuntimeProfile(...)` `:761`) and import-time validation. A new focused test for delegation validation would be net-new.

## Caveats / Not Found

- **se-smoke retirement is the key coupling.** Several tests are hard-coded to `se-smoke` (`test_install.py:344-377`, `test_generate.py:583`). If R1/goal replaces se-smoke with the two real agents, those tests must be rewritten; if se-smoke is kept alongside, they still pass but the canonical se-smoke body says to remove it "when the first real worker role ships." Design must decide keep-vs-retire; PRD/acceptance does not state it explicitly.
- No installer code change is required for the agent *kind* — the plumbing (07-25-agent-artifact-kind) already generalized install/remove/provenance.
- Delegation adds no manifest rows and no install targets (it is skill-body/overlay + registry metadata), so `test_install.py`/`test_release_gate.py` see it only via the generated Claude skill bytes and version bump.
